# probe: behavior-review（行为正确性）

**required: true** ｜ **requires: []**

检查本次改动引入或触发的行为缺陷。审查范围和源码版本以 `SKILL.md` 的“确定审查范围”为准；
不依赖规则包，也不受规则扫描的语言扩展名限制。
按需追踪实际调用链，不受 `impact-analysis` 的一层 fan-in 限制；未找到调用方不能单独证明内部逻辑正确或错误。

## 行为取证与检查

对关键行为，先按顺序取证，再推演和定级：

1. 定位实际调用的完整方法签名，读取对应接口声明及该方法自身的契约；不能用同名重载或相似接口代替。涉及解析 / 校验时，先确认输入语言和依赖版本，主动补读相应语法或格式契约，不能只用当前样例代表合法输入。
2. 涉及模型或缓存读取时，沿对象获取、创建和包装路径，读取实际返回实现及相关覆写方法。涉及序列化 / 渲染时，沿调用链补读实际包装、渲染和解析实现，并对照相关旧入口；不能仅按接口字段、方法名或默认实现推断行为。
3. 结合上述材料推演触发条件与结果，再按输出契约定级。语法依据、实际实现链路或合法触发输入的可达性未核实时，注明具体缺口，不得当作已证实缺陷或宣称检查完整。

对本次改动影响的主要路径，结合入口、调用方和上下文检查：

- 条件分支是否符合预期，是否存在判断反向或遗漏分支。
- 状态转换是否允许，副作用是否在正确条件下执行。
- 空值、空集合和数值边界是否处理正确。
- 异常或部分失败后，状态与资源是否正确处理。
- 重复调用、重试、并发是否破坏业务约束。

针对主要行为变更，先从 diff 定位相关处理点，再选择具体反例，沿下列路径推演，最后定级：

- **解析 / 校验**：依据输入语法或契约选择合法的等价写法，沿“解析 → 校验 → 使用”核对结果是否一致，是否绕过校验。
- **序列化 / 模板渲染**：沿实际转换顺序追踪变量值，选择引号、反斜杠或换行等相关输入，核对转义、解码是否改变原值或破坏结构。

未涉及上述处理时，按主要行为另选反例。检查记录统一说明：
**处理点位置 → 触发条件及具体输入 → 预期行为及依据 → 相关代码路径 → 实际行为与后果**。
已确认问题写入 finding 的 `evidence`；未完成或证据不足的检查列为未验证项及限制，不得笼统记为“已检查”。未运行时标明“静态推演”，不得称为已复现。

预期依据可来自接口契约、设计、已有测试或明确的代码不变量，不得自行编造业务规则。

## 判定与上报

行为 finding 不要求已有规则 ID，也不受 `repo-guard` 仅报告 CRITICAL / HIGH 级别规则的限制。
