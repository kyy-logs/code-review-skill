# 独立行为正确性探针设计

日期：2026-10-29。设计基于 main 提交 `494a39b`；本文件描述待实施方案，尚未修改 skill。

## 目标与依据

用户确认：`repo-guard` 只负责仓库规范，通用行为正确性由独立探针承担。重点是应报行为缺陷的识别，同时保持职责清晰和成本可控。

当前 `repo-guard.md` 的 3.3 已包含完整的行为取证、路径推演和反例检查，专项回归曾命中三个已知目标。本次迁移这些要求，不另写一套行为检查清单。该单次结果不能证明拆分后提高召回率。

选择独立探针，而非移入 `impact-analysis`：后者负责调用方、兼容性、性能和架构影响，默认调用方追踪深度为一层、required 为 false，不适合作为核心行为检查的唯一归属。

## 职责与依赖

| 探针 | 责任 | required | requires |
|---|---|---|---|
| behavior-review | 本次改动的控制流、状态、异常、边界、解析及数据转换是否符合实际契约或不变量 | true | [] |
| test-coverage | 相关测试的断言、场景和稳定性是否有效；按现有约定处理可选覆盖率 | true | [] |
| repo-guard | 依据所选规则包扫描、加载与复核仓库规范 | true | [rules] |
| impact-analysis | 调用方适配、外部兼容性、性能和架构影响 | false | [] |

`requires: []` 表示不依赖额外规则包，仍使用主流程必需的 Git 范围和源码。行为检查不受规则扫描的语言扩展名限制，按实际改动读取源码或配置。

规范缺失时，repo-guard 仍按既有规则记 error；行为探针可以独立完成检查。其余探针继续执行并交付结果，不把规则错误当作行为检查通过。最终门禁仍受 required 探针错误阻塞。

## 执行方式

注册顺序为 `behavior-review → test-coverage → repo-guard → impact-analysis`。核心行为检查先执行，其余三个探针保持现有相对顺序。

由同一主执行器顺序执行，共享固定的审查模式、base/head、变更清单、diff 及已读取的目标版本上下文。不新增独立代理，不默认增加第二遍全仓阅读，也不引入新的上下文缓存文件。

必要上下文按需补读；需要判断行为可达性时允许追踪实际调用链，不套用影响分析的一层 fan-in 限制。未找到调用方不能单独证明内部逻辑正确或错误。

## 行为探针内容

新增 `references/probes/behavior-review.md`，迁入原 repo-guard 3.3，包括：

- 实际方法签名、目标版本契约和代码不变量的核对。
- 实际返回实现、包装与覆写路径的追踪。
- 解析语法、依赖版本、序列化与渲染转换链的主动取证。
- 相关分支、状态、空值、数值边界、异常、资源及重试并发检查。
- 根据实际处理点选择反例，并记录预期依据、路径和结果。
- 区分静态推演与运行复现，未核实材料列为限制。

证据仍采用“触发条件 → 代码路径 → 预期依据 → 实际行为与后果”。severity、finding 状态与执行状态引用共享输出契约，不复制定级表。行为 finding 不要求规则 ID，也不受规范检查仅报告 HIGH/CRITICAL 规则的限制。

repo-guard 删除迁出的完整正文，只保留职责指引。规则扫描与规范语义复核继续按需加载相关规则，不默认加载全部规则。

## 重复问题与交接

根因及后果相同的问题保留首次 finding ID；后续探针引用该 ID，补充自己的规范依据、测试或调用方证据，不新增同根因 finding。

独立测试缺陷或独立兼容性破坏可以单独建项，须说明与已有问题的区别。impact-analysis 可以自行发现行为或兼容性问题，不要求所有问题先由行为探针发现。

补充说明写入现有的人类报告非自动区域；不新增 JSON 字段，不通过复制已有问题来附加证据，不擅自改动此前探针的原始记录。共享输出契约已有的独立问题归组要求继续适用。

## 输出及兼容性

行为探针写 `probes/behavior-review.json`，finding ID 使用 `behavior-review-<序号>`；无发现也输出有效记录。

沿用现有 passed/failed/skipped/error 和 finding/reviewer/reconciliation 语义。behavior-review 的 failed/error 按 required 计入阻塞；critical/high finding 继续进入 reconciliation。

同步、reviewer 和报告脚本目前按注册表读取探针。实施时验证新增探针能被计数、裁决、渲染、校验，不假定无需适配，也不预先重写脚本。未发现不兼容时不改脚本。

迁移后的 finding 前缀发生变化，回归按问题机制匹配；不重编号、改写或重新同步历史产物。历史结果继续按各轮冻结注册表解释，新运行使用新的四探针注册表。

## 验证与验收

离线验证：

- 新探针缺记录或记录非法时，不能被汇总成零发现或放行。
- 有效四探针记录可同步、渲染并通过展示校验；行为 finding 可被 reviewer 正确引用。
- 行为探针的 open high 和执行 error 均按现有规则阻塞，正常对照记录不额外制造 finding。
- 检查职责路由与引用，迁出的行为检查要求无丢失；运行 skill 校验和受影响的现有离线测试。

行为效果验证：后续明确授权的模型回归使用冻结新版本，检查已知行为目标、正常对照、重复项和成本。按实际输入范围报告结果，不将机械集成验证称为召回能力通过。

设计验收标准是职责分离、检查能力没有被文字迁移遗漏、现有结构化输出链兼容；不预设拆分一定提高识别率或节省 token。
