# 四探针并行执行设计

> 当前范围已按用户要求精简：仅保留四代理并行，各自直接写现有探针 JSON；不实现下文的去重映射、raw 分层或合并脚本。下文保留为此前设计记录，不作为本次实施要求。

日期：2026-10-30

分支：`codex/parallel-review-probes`

## 目标与范围

将现有四探针交给独立代理并行执行，缩短一次审查的墙钟时间。保留探针职责、三档 severity、独立 reviewer 及现有报告和门禁语义。不承诺 tokens 下降或四倍提速。

本次不增加规划代理、不更换模型、不修改被审代码、不开展付费模型评测。当前工作树中三行“查询合并、首次读取带行号”的修改保留。

## 当前实现与必要变化

`SKILL.md` 步骤 3 和 `references/probes.yaml` 要求顺序执行。后续探针可引用此前 finding 的 ID，避免重复。

`sync-results.py` 校验独立探针 JSON，按 finding ID 汇总，不推断两个不同 ID 是否属于同一问题。直接并行会破坏“引用首次 ID”的前提，造成重复计数。因此并行派发和汇总去重必须一起实现。

## 采用的流程

1. 主执行器固定模式、base/head、变更清单和 diff，检查输入，创建本轮目录。
2. 向四个独立代理分别提供同一份范围、skill 路径、对应探针说明、输出契约和独立输出路径。每个代理只执行自己的探针，按需读取源码，不重跑完整 SKILL 流程，不派发嵌套代理。
3. 各代理把原始结果写入 `probes/raw/<name>.json`。文件格式沿用现有探针格式，ID 使用各自探针前缀。代理不得写其他探针、最终报告、指标或共享事件日志。
4. 主执行器等待所有结果。宿主并发槽位不足时分批派发；没有独立上下文能力时明确记录限制并串行执行。不得把四次同步调用称为并行。
5. 主执行器根据全部候选判断跨探针重复，写 `probe-merges.json`；由合并脚本验证映射并生成现有链路使用的 `probes/<name>.json`。
6. 现有 sync、review-mode、reviewer、报告渲染和门禁按原流程继续，只有主执行器运行这些共享写操作。

`duration` 记录每个代理从派发到结果返回的观察耗时（整数秒，说明包含调度等待），不将四项之和称为本轮墙钟时间。缺少测量时不编造耗时。

## 去重契约

原始候选 JSON 保存后不改写。最终 JSON 是去重后的派生记录，不冒充代理原始返回；保留所有最终 finding 的原始 ID、severity、status 和证据。

`probe-merges.json` 必须存在；没有重复也显式写空数组。结构：

```json
{
  "duplicates": [{
    "id": "impact-analysis-1",
    "canonical_id": "behavior-review-1",
    "reason": "两条候选具有相同根因及后果；此处填写具体代码路径和对应依据"
  }]
}
```

合并决策由主执行器作语义判断；脚本只验证映射和生成结果，不用位置、关键词或相似摘要自动猜测根因。

- 只有跨探针、同根因且同后果的问题才能合并。同一文件、同一行不充分。
- canonical 使用注册表中更靠前探针的原始 ID，不由代理完成时间决定。
- 最小版本只合并 severity 和 status 一致的候选；存在分歧时保留独立候选并在报告解释，不擅自降低级别或裁定状态。
- 重复 ID 在映射中只能出现一次；所有引用必须存在，不允许自引用、链式引用或环。
- 不删除候选中的独有证据：原始文件始终保留，报告非自动区域列明被合并 ID、canonical ID、原因及补充依据。最终自动事实区不重复计数。
- 脚本不改写 canonical 的摘要或证据。独立缺陷保持分项。

合并脚本先复用现有 JSON 校验，验证全部候选及映射，全部有效后才写派生文件。验证失败时不产生部分结果或运行 sync；一次生成期间只有主执行器写这些文件。

正常候选的 passed/failed 根据其派生 findings 中是否存在 open high 重新计算。error 及 skipped 原样保留，不因合并掩盖输入或执行错误。原始 failed 仍可在 raw 文件追溯。

复审时为本轮新结果重新合并，不能复用旧映射掩盖新增候选；历史原始记录按原约定保留。

## 异常处理

- 缺失、格式错误、未知探针、重复 ID、非法合并引用必须失败，不能静默省略或视为零结果。
- 子代理失败时，主执行器记录具体执行错误；有已返回候选则保留，不虚构 finding。其他代理继续完成。
- 合并只去重，不授予 required 探针错误放行权限；所有现有 high reconciliation 约束保留。
- 汇总脚本不具备派发代理的能力；并行由宿主执行器按 SKILL 指引完成。离线测试不证明宿主已实际并发。

## 计划涉及的文件

- `skills/code-review/SKILL.md`：独立代理派发、等待、原始结果、合并和单写者交接。
- `skills/code-review/references/probes.yaml`：执行模式改为 parallel，注册顺序保留用于稳定去重。
- `skills/code-review/references/output-schema.md`：原始候选与派生结果的区别、去重映射和状态规则。
- `skills/code-review/scripts/merge-probes.py`：复用既有校验、校验合并映射、生成派生探针 JSON。
- `tests/test_parallel_probes.py`：并行结果交接和合并不变量的离线测试。
- `README.md`、`README.zh-CN.md`：同步说明并行、宿主容量限制及成本边界；不改变发布评测数字。

不修改四份探针职责文档、reviewer 剧本、宿主 reviewer 适配器和安装逻辑；新脚本随现有 skill 目录复制安装。若离线测试发现必须修改上述边界外文件，先说明具体原因。

## 验证与验收

先运行现有离线测试取得基线，再为合并功能建立失败测试后实现：

1. 四份结果以不同完成顺序交付，派生结果和 ID 不变；无重复时全部保留。
2. 合法重复只计一次，原始文件字节不变，剩余独立问题不丢失。
3. severity/status 分歧、未知引用、同探针合并、自引用、链和重复映射均拒绝。
4. required error、缺失结果、非法状态仍失败；重复移除后的派生状态与 findings 一致。
5. 非法输入不改写已有派生结果；全部验证后才能替换输出。
6. 派生结果进入现有 sync、render-report、verify-report 和 gate 链路，计数一致。
7. Bash 相关检查使用现有 Git Bash；执行 skill 校验及 git diff --check。

本次验收只证明编排契约和离线汇总机制。真实并发、总墙钟、tokens、缺陷召回和重复率需要之后在用户授权的宿主运行中测量；不将夹具执行等同于真实模型收益。

## 设计自检

- 四代理只写各自 raw 文件；主执行器是派生结果和共享日志的唯一写者。
- 原始记录与派生记录名称、用途明确，不改变 reviewer 接收的现有字段。
- 去重只覆盖同级别同状态的明确重复，保留有分歧的结果，避免借去重降低阻塞。
- 没有新增依赖、强制模型或未经验证的提速数字。
