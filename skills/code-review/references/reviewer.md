# 独立 Reviewer 剧本

由宿主提供的独立上下文逐条核验证据及反例，并检查跨探针的组合风险。
不得仅接受主会话或探针的结论，也不因无法证伪而确认问题。

## 1. 执行边界

- 只读证据并返回裁决，不写文件、不改代码、不跑构建或测试、不补跑探针。
- shell 仅用于 `git diff`、`git show`、`grep`、`cat` 等读取证据的操作；这是执行约束，不代表工具层已强制只读。
- 不依赖主会话的对话历史；规则、输入与代码须从提供的路径读取，读不到时说明缺失，不凭转述补齐。

## 2. 输入

派发时提供 skill 安装目录、被审项目根目录、`slug`、审查范围及本次产物目录。
`references/`、`assets/`、`scripts/` 路径相对 skill 安装目录；被审代码与 `docs/work/` 路径相对项目根目录。

| 输入 | 来源 |
|---|---|
| 审查目标与验收标准 | 用户任务说明及逐条验收摘要（如有）；缺失时注明 |
| 审查范围与改动 | 模式、base、目标、变更文件清单及差异；按 `SKILL.md`“确定审查范围”读取对应源码，worktree 须包含未跟踪新增文件 |
| 探针结果 | 产物目录下各 `probes/<探针名>.json`，包含执行状态和 findings；scorecard 可选 |

## 3. 逐条裁决

逐条读取 finding 的依据并独立核对。有符合只读边界的 `repro` 时，优先执行；无法执行时说明原因，改为读取证据核对。
裁决引用已有稳定 ID；缺失或重复 ID 属于输入错误，返回主会话修正，不自行补号。

每条 finding 从以下五种裁决中选择：

| 裁决 | 条件与要求 |
|---|---|
| `confirmed` | 证据成立，问题真实存在，保持原 severity |
| `downgraded` | 问题真实但定级偏高，写明最终级别、适用判据及证据 |
| `rejected` | 证据不成立或属于误报，须给出具体驳回依据，保持原 severity |
| `escalated` | 问题被低估，写明最终级别、适用判据及证据；须主动检查是否需要升级 |
| `unverified` | 既不能确认也不能证伪，说明具体缺口，保持原 severity 和 `status=open` |

定级遵循 `references/output-schema.md` 第 2 节的完整规则，包括行为类问题、组合风险与测试缺口。
引用的依据真实存在但不足以定论时，判为 `unverified`；经核对，finding 没有任何可读依据、不满足“没有依据的不算 finding”的准入要求时，判为 `rejected` 并说明核对结果。未仔细核对不能当作证据不足。

high 未处置时持续阻塞合入，`unverified` 或“已知悉、暂不处理”不能作为放行依据。
未完成的裁决须明确列出，保留原 severity 和 `status=open`，不补造裁决或宣称已全部复核。

## 4. 跨探针检查

除单条裁决外，还须检查：

- 同一处代码上的不同问题是否相互作用，造成更严重后果。
- `skipped` / `error` 探针原本负责的风险是否仍有检查缺口。
- 覆盖率通过时，新增测试是否有无效断言或未验证预期行为的问题。
- 各探针结论是否互相矛盾。

组合升级须说明相互作用路径及共同后果，不能仅因多个 medium 并存或缺少测试就升级。

## 5. 输出与交接

1. 按 `references/output-schema.md` 返回一个 JSON 对象：`decision=run`，`verdicts` 逐条引用已有 ID。
   核验证据时发现的遗漏问题也须报告，按完整 finding 格式填入 `findings`，编号为 `R<序号>`、`probe=reviewer`，不冒记为原探针问题。
2. 另返回跨探针检查结论及未完成项，不手填计数。
3. 主会话将 JSON 原样保存为 `reviewer.json`，不得改写裁决或增强、减弱结论；在报告中注明是否原样落盘。
   主会话执行 `collect-metrics sync {slug}` 派生最终计数，再通过 `render-report` 生成人类报告事实区域。

`RECONCILE_PENDING > 0` 时阻塞合入；计数包含 reviewer 新增的 high 问题。
